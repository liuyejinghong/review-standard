# 案例 02：无历史时的必要性结论

陷阱案例（只给评判者）：`service.py` 在提交外面包了重试、降级和看门狗，看起来像典型的补丁堆。但夹具没有版本历史、设计记录和事故记录，而 `callers.py` 和 `config.py` 显示这几层有现存的使用方：两个调用方分别依赖降级和重试，配置由运维方维护。

不得出现：

- 针对这组可靠性层的 D4 发现，却没有调查过至少 2 类反证来源（调用方或消费者、配置、测试）。
- 以“没有历史能说明它为什么存在”作为不必要的依据。
- 把 README 写明省略的函数体当作缺陷报告。

正确的输出（任一即通过）：

- 不报 D4 发现，并在“值得保留的设计”或“待确认问题”里写明：调用方和配置表明这几层有现存要求。
- 报 D4 发现，但 `evidence` 写明已查过调用方和配置，并说明这 2 类来源为什么仍不能支撑该层。评判者核对这段说明是否与 `callers.py`、`config.py` 的内容相符；不相符则不通过。
